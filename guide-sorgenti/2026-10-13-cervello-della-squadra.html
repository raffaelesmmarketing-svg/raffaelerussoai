Il cervello della squadra: le stesse skill di Claude per tutti

Come lo faccio io con la mia collaboratrice. Le istruzioni che insegno al mio Claude stanno in un archivio privato su GitHub, e il suo Claude, ogni volta che parte, scarica l'ultima versione. Correggo una skill una volta sola, e alla prossima apertura la usiamo già tutti e due.

Prima di cominciare
Tre cose da sapere

Cos'è una skill

È una cartella con dentro un file di istruzioni, SKILL.md: cosa deve fare Claude, come, e quando usarla. Claude Code le trova da solo nella cartella .claude/skills e le usa quando la richiesta è quella giusta. Le mie sono cose tipo: come si monta un reel, passo per passo, con le mie regole.

Il problema che risolve

Prima ognuno usava l'intelligenza artificiale a modo suo, e i risultati non si somigliavano mai. Se miglioravo un'istruzione, dall'altra parte continuavano con quella vecchia, e me ne accorgevo solo guardando il lavoro finito.

Cosa ti serve

Claude Code su ogni computer della squadra, un account GitHub per ciascuno e un archivio privato, che è gratis. Non serve saper programmare: i comandi li scrive Claude, tu li leggi e li approvi.

La guida
I sei passaggi

Si fanno una volta sola. I primi tre sul tuo computer, gli altri su quello del collaboratore.

01
Crea l'archivio privato
Come

Su github.com clicca «New repository», dagli un nome (il mio si chiama «cervello»), scegli «Private» e crealo. Poi in Settings, Collaborators, invita chi lavora con te: gli arriva una mail da accettare.

Le cartelle

skills/ per le tue skill. saperi/ per i documenti che le skill citano, come le regole del tuo marchio o gli esempi buoni. regole/ per le decisioni che valgono per tutti. E una cartella per ogni collaboratore, dove scrive solo lui.

Perché privato

Dentro c'è il tuo metodo di lavoro. Lo vede solo chi inviti tu.

02
Decidi cosa ci va dentro
L'elenco

Non ci finisce tutto. Io tengo un elenco, che chiamo «manifesto», con le skill e i documenti da condividere: si pubblica solo quello che c'è scritto lì. Per aggiungere una skill si aggiunge una riga.

Mai dentro

Chiavi, password, token e dati dei clienti. E niente video pesanti: quelli restano su Drive, nell'archivio c'è solo il testo.

03
Pubblica dal tuo computer
La richiesta
Da copiareCopia nell'archivio ~/cervello le skill e i documenti che trovi nell'elenco manifesto.json, uguali a come sono da me. Prima mostrami quali file cambiano. Poi fai commit e push, con un messaggio di una riga che dice perché.
Quando

Solo quando una skill è finita e ti torna. Mai a metà lavoro: dall'altra parte userebbero una versione che non hai ancora deciso.

04
Collegalo sul computer del collaboratore
Come

Lui scarica l'archivio e collega le skill nella sua cartella ~/.claude/skills. Sono collegamenti, non copie: quando l'archivio si aggiorna, la skill è già quella nuova. Il modo più semplice è fargli incollare questo al suo Claude, insieme all'hook del passaggio 5.

Da incollare
Da incollare al suo ClaudeCiao Claude. [Nome] ha creato un archivio privato su GitHub, [utente]/cervello, con le skill che usiamo tutti e due.

1. Controlla con gh auth status che io veda l'archivio. Se non lo vedo, fermati: devo accettare l'invito.
2. Scaricalo in ~/cervello e collega in ~/.claude/skills ogni cartella di skills/, come collegamento e non come copia. Se ho già una skill con lo stesso nome, non toccarla.
3. Aggiungi in ~/.claude/settings.json l'hook di avvio che ti incollo qui sotto (lo script aggiorna.sh è già nell'archivio), dopo aver fatto una copia di riserva del file.
4. Le skill di [Nome] non le modifichi: se serve un cambio, scrivi la proposta in ~/cervello/da-[il mio nome]/proposte/ e dimmelo.

Prima mostrami il piano, poi aspetta il mio ok.
05
L'aggiornamento a ogni avvio
Come funziona

Il pezzo che fa la differenza è un hook: un comando che Claude Code lancia da solo all'avvio di ogni sessione. Il nostro scarica l'ultima versione dell'archivio e collega le skill nuove. Gira in sottofondo, e la sessione parte subito.

Il file
aggiorna.sh, nell'archivio#!/bin/bash
# scarica l'ultima versione e collega le skill nuove
git -C ~/cervello pull --ff-only -q
mkdir -p ~/.claude/skills
for s in ~/cervello/skills/*/; do
  nome=$(basename "$s")
  [ -e ~/.claude/skills/"$nome" ] || ln -s "${s%/}" ~/.claude/skills/"$nome"
done
L'hook
in ~/.claude/settings.json{
  "hooks": {
    "SessionStart": [
      { "hooks": [ { "type": "command",
        "command": "nohup bash ~/cervello/aggiorna.sh >/dev/null 2>&1 &" } ] }
    ]
  }
}
Attento

Se nel file ci sono già altre impostazioni, l'hook si aggiunge a quelle. Fallo fare a Claude, non incollarlo sopra a quello che c'è.

06
Chi modifica cosa
La regola

Le skill che scrivi tu le modifichi solo tu. Il Claude del collaboratore le usa ma non le cambia: se serve una modifica, scrive la proposta nella sua cartella e decidi tu. Così le istruzioni non si rovinano a forza di ritocchi fatti da due parti.

La guardia

Sul suo computer c'è un secondo hook, PreToolUse: prima di ogni modifica a un file guarda dove sta, e se è una tua skill la ferma. Chiedi a Claude di scrivertelo: è un controllo di poche righe.

Le sue skill

Quelle che crea lui stanno in una cartella sua, e le potete modificare tutti e due.

Per non litigare
Le tre regole che teniamo

Una decisione, un file

Ogni regola che vale per tutti sta in un file suo, nella cartella regole/, con chi l'ha decisa e quando. Una regola superata non si cancella: ci si scrive sopra quale l'ha sostituita.

Se due regole si contraddicono, non sceglie Claude

Si scrive un file in regole/da-decidere/ e decide chi ha la responsabilità di quella parte. Fatto sta che così nessun Claude riscrive di nascosto una decisione presa da un altro.

Prima si aggiorna, poi si scrive

Prima di toccare l'archivio si scarica l'ultima versione. Dopo, subito commit e push, con un messaggio che dice perché.

Da dove parti
Domani, una skill sola

Scegli una cosa che fate in due ogni settimana e che vi viene sempre diversa: un tipo di mail, un formato di contenuto, un preventivo. Chiedi al tuo Claude di scriverla come skill, pubblicala, e fai aprire al collaboratore una sessione nuova. Se la vede e la usa, il cervello funziona.
